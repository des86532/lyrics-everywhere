# LE-LRC v1 空耳格式規格

LE-LRC v1 是 LRC 相容的空耳檔格式。檔案只要有 `[le:version:1]` 標頭，就能被 Lyrics Everywhere 辨識；沒有這個標頭的檔案會被拒絕。使用者可以用任何文字編輯器手寫，也可以把應用程式匯出的檔案分享給朋友。

## 基本規則

- **編碼**：UTF-8，副檔名 `.lrc`。
- **大小限制**：單檔最大 60,000 bytes，最多 2,000 行，每行最多 500 字元。
- **換行**：`\n` 或 `\r\n` 皆可。
- **大小寫**：標頭名稱不分大小寫（`[LE:VERSION:1]` 與 `[le:version:1]` 等效）。

## 標頭

每個標頭獨占一行，順序不限。

| 標頭 | 必填 | 說明 |
|---|---|---|
| `[ti:歌名]` | 否 | 歌名。可省略；「整理並檢查」會以目前曲目的標題補上。 |
| `[ar:歌手]` | 否 | 歌手。可省略；「整理並檢查」會以目前曲目的歌手補上。 |
| `[al:專輯]` | 否 | 專輯名。讀入後忽略。 |
| `[by:作者]` | 否 | 作者。 |
| `[length:mm:ss.xx]` | 否 | 歌曲音檔長度，例如 `[length:04:34.00]`。品質檢查用它判斷時間是否超出長度。 |
| `[offset:±ms]` | 否 | 全檔時間平移（毫秒）。解析時套用到每個時間戳，並夾在 0 以上。 |
| `[re:]`、`[ve:]` | 否 | 標準 LRC 標頭，讀入後忽略。 |
| `[le:version:1]` | **是** | 格式版本。缺少時視為非 LE-LRC 檔（`E_NOT_LE_FORMAT`）；版本不是 `1` 時為 `E_BAD_HEADER`。 |
| `[le:lang:ko]`、`[le:lang:ja]`、`[le:lang:other]` | 否 | 原文語言。省略時自動判斷（見下方「語言判斷」）。 |
| `[le:anchor:song]` | 否 | 時間軸以歌曲音檔為準。省略時等同此值。 |
| `[le:anchor:youtube:<videoId>]` | 否 | 時間軸以指定的 YouTube 影片為準。`<videoId>` 為 11 個字元。 |

### 時間軸語意

- **`anchor:song`**：時間戳以歌曲音檔 0:00 為準，與 LRCLIB 相同。播放 MV 時，可由使用者手動校正該影片的起點偏移。
- **`anchor:youtube:<id>`**：時間戳以該支影片的播放時間為準，適用於組曲、翻唱與剪輯版。此類檔案的時間軸已以影片為準，不另外加上起點偏移，但仍可由使用者手動微調。只有目前播放的影片 ID 與 `<id>` 相同時才能套用。

## 歌詞行

歌詞行的格式為 `[mm:ss.xx]文字`。

- 時間戳可以是 `[mm:ss.xx]`、`[mm:ss.x]` 或 `[mm:ss]`。
- 同一行可以放多個時間戳，例如 `[00:01.00][00:30.00]x`；應用程式會展開成兩行。
- `<mm:ss.xx>` 逐字時間標記會被移除，保留文字。
- **不允許沒有時間戳的歌詞行**（`E_UNTIMED_LINE`）。空白行可以忽略。
- 空字串文字（`[00:45.00]`）可作為間奏或段落標記。

### 配對規則

應用程式會把所有歌詞行展開，依時間分組：

1. 同一時間的行，依檔案中**出現的順序**配對。
2. 同一組的**第 1 行是原文**，**第 2 行是空耳**。
3. 一組只有 1 行時，代表該句**沒有空耳**。
4. 同一時間出現 3 行以上屬於錯誤（`E_TOO_MANY_AT_TIMESTAMP`）。

### 行數與順序

- 解析後依時間**穩定排序**。若檔案中的行不是依時間順序排列，會出現 `W_TIMESTAMP_ORDER` 警告（只提醒一次）。
- 解析結果為 0 行時為錯誤（`E_EMPTY`）。

## 範例 A：韓文，時間軸以歌曲為準（`anchor:song`）

```
[ti:봄날]
[ar:BTS]
[length:04:34.00]
[le:version:1]
[le:lang:ko]
[le:anchor:song]
[00:15.20]나를 사랑으로 채워줘요
[00:15.20]那路 撒郎呃路 七我走有
[00:19.80]사랑의 배터리가
[00:19.80]撒郎耶 呸特里嘎
[00:24.00]
```

說明：

- 第一組（`00:15.20`）有兩行，第 1 行是韓文原文，第 2 行是空耳。
- 第二組（`00:19.80`）同樣有原文與空耳。
- 最後的 `[00:24.00]` 是空白文字，作為間奏標記，不需要空耳。

## 範例 B：韓文，時間軸以影片為準（`anchor:youtube`）

```
[ti:봄날 (Live Version)]
[ar:BTS]
[le:version:1]
[le:lang:ko]
[le:anchor:youtube:abcdefghijk]
[00:45.20]나를 사랑으로 채워줘요
[00:45.20]那路 撒郎呃路 七我走有
[00:49.80]사랑의 배터리가
[00:49.80]撒郎耶 呸特里嘎
```

說明：

- 時間戳是影片播放時間，因此第一句從 `00:45.20` 開始（前面有 45 秒的前奏）。
- 只有當目前播放的影片 ID 是 `abcdefghijk` 時，才能套用此檔。
- 此範例的影片 ID 為示意用的 11 字元字串。實際使用時請填入真實的 YouTube 影片 ID。

## 整理並檢查的輸入

「整理並檢查」接受下列三種輸入。若可以，會自動產生符合本規格的 LE-LRC 草稿：

- **已含時間戳**：任一行以 `[mm:ss…]` 開頭。若缺少 `[le:version:1]` 會自動補上，並補齊 `[ti]`、`[ar]`、`[length]` 與 anchor。
- **逐句交錯**：沒有時間戳，原文一行、空耳一行交錯排列。原文會與目前已載入的同步歌詞比對，因此需要先有同步歌詞。能對上的原文行數需至少為需要空耳句數的一半（`對上行數 × 2 ≥ 需要空耳句數`）；不足時改當成「只有空耳」處理，行數不符即得到 `F_COUNT_MISMATCH`。
- **只有空耳**：沒有時間戳，每行一句空耳。行數必須與需要空耳的句數相同，同樣需要同步歌詞。

沒有同步歌詞、又沒有時間戳時會得到 `F_NEED_SYNCED_SHEET`。只有空耳且行數不符時會得到 `F_COUNT_MISMATCH`。

## 語言判斷

1. 若有 `[le:lang:x]`，以它為準。
2. 若未宣告，統計原文行：
   - 含韓文字的行數多於含假名的行數，且前者大於 0，判為 `ko`。
   - 否則只要有含假名的行，判為 `ja`。
   - 其餘判為 `other`。

## 品質檢查

檢查結果分為三種評級：

- **`pass`**：通過。
- **`warn`**：可以套用，但有提醒。
- **`reject`**：未通過，禁止套用。只要有任一錯誤，評級就是 `reject`。

### 需要空耳的原文行

| 語言 | 原文行的判定 |
|---|---|
| `ko` | 含韓文字。 |
| `ja` | 含假名或漢字。 |
| `other` | 含字母，且不含漢字。 |

`coverage` 為「有非空空耳的需要空耳行數」除以「需要空耳行數」。

### 錯誤（reject）

| 代碼 | 條件 | 說明 |
|---|---|---|
| `E_NOT_LE_FORMAT` | 缺少 `[le:version:1]` | 不是 LE-LRC 檔。 |
| `E_BAD_HEADER` | 版本不是 `1` | 目前只支援版本 1。 |
| `E_UNTIMED_LINE` | 非空白行沒有時間戳 | 附行號。 |
| `E_TOO_MANY_AT_TIMESTAMP` | 同一時間超過 2 行 | 附行號。 |
| `E_EMPTY` | 解析後 0 行 | 檔案沒有任何歌詞行。 |
| `E_TOO_LARGE` | 超過 60,000 bytes、2,000 行或單行 500 字元 | 檔案太大。 |
| `E_NO_SOURCE_LINES` | 需要空耳的行數為 0 | 沒有可以標注空耳的原文行。 |
| `E_LOW_COVERAGE` | `coverage < 0.8` | 空耳覆蓋率不足 80%。 |
| `E_SOURCE_IN_KONGER` | `ko`／`ja` 的空耳行含韓文字或假名 | 通常是原文與空耳順序貼反了。附行號。 |
| `E_KONGER_EQUALS_ORIGINAL` | 空耳與原文相同（忽略標點與大小寫） | 空耳不能只是原文的複製。 |
| `E_ANCHOR_MISMATCH` | `anchor:youtube:<id>` 與目前影片不同 | 這個檔案不是給這支影片用的。 |
| `E_TIME_BEYOND_DURATION` | 最後一句超過參考長度＋2 秒 | `anchor:song` 使用 `[length]`；`anchor:youtube` 使用影片長度。缺少參考長度時跳過。 |
| `E_SYLLABLE_MISMATCH_RATE` | 已檢查的音節行 ≥ 4 句，且不符比例 > 30% | 空耳字數與原文音節數差距太大。 |

### 警告（warn）

| 代碼 | 條件 | 說明 |
|---|---|---|
| `W_TIMESTAMP_ORDER` | 行不是依時間順序排列 | 應用程式會自動排序。 |
| `W_SYLLABLE_MISMATCH` | 單行音節數不符 | 附行號與「原文 s 音節，空耳 k 字」。 |
| `W_KONGER_TOO_LONG` | 空耳超過 80 字元 | 可能影響顯示。 |
| `W_ORPHAN_KONGER` | 逐句交錯模式中，沒有前導原文的空耳行 | 該行已捨棄。附行號。 |
| `W_UNMATCHED_LINE` | 逐句交錯模式中，輸入的原文找不到對應的歌詞時間軸 | 該句已略過。附輸入行號。 |

### 音節數檢查

只檢查 `ko`、`ja`，且只檢查有空耳的行。

- **原文音節數 `s`**：
  - `ko`：韓文字數。
  - `ja`：假名字數，扣除小假名（ぁぃぅぇぉゃゅょゎァィゥェォャュョヮ）、促音（っ／ッ）與長音（ー）。原文含漢字時，該行不檢查。
- **空耳單位數 `k`**：漢字數＋連續 ASCII 英文字母段數＋連續注音段數（U+3105–312F）。
- **通過條件**：
  - `ko`：`|k − s| ≤ max(1, ceil(0.25 × s))`。
  - `ja`：`floor(0.5 × s) ≤ k ≤ ceil(1.25 × s) + 1`。
- `s == 0` 時不檢查。

## 常見錯誤

- **把原文與空耳貼反**：`ko` 的第一行應是韓文，第二行應是中文空耳。順序反了會得到 `E_SOURCE_IN_KONGER`。
- **只貼文字，沒有時間戳**：歌詞行必須有時間戳才能進入 LE-LRC 檔案本身（`E_UNTIMED_LINE`）。若是在「整理並檢查」中貼上沒有時間戳的文字，請參考上方「整理並檢查的輸入」。
- **時間戳超過歌曲長度**：檢查 `[length:]` 是否正確，或是否誤用了 `anchor:song` 而非 `anchor:youtube`。
